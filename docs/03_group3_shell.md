как между передними и задними, так и между верхними и нижними...

прямоугольный фальц по ТЗ с язычком/каналом, самоцентрирующим скосом
и симметричным утоплением наружной поверхности — всё это теперь
убрано целиком). Швы Перед/Зад снова получают НОМИНАЛЬНУЮ геометрию
без какого-либо интерлока: обе половины используют одни и те же
`Внешние_точки`/`Внутренние_точки` (шаг 3 → шаг 5 напрямую, без
"male"/"female" развилки).

Удалённые входы: `Фальц_глубина_мм`, `Фальц_ширина_мм`,
`Фальц_утопление_мм`, `Фальц_зазор_мм`, `Фальц_скос_град`,
`Кромка_радиус_мм` (в более ранних версиях — `Паз_глубина_мм`,
`Паз_ширина_доля_кольца`) — их больше нет ни в коде, ни в UI
модификатора.

**Эффект на замкнутость геометрии:** вместе с аналогичным удалением
паза/шипа в Группе 5 это убрало ЕДИНСТВЕННЫЙ источник остаточных
Boolean-/сшивочных дефектов в проекте. Все кейсы `verify_group3.py`
и без того всегда проходили `Провер_ВСЕ_OK=True` (фальц строился не
через Boolean, а через прямое смещение позиций точек, поэтому сам по
себе он не порождал "дырявых" рёбер) — но теперь геометрия шва ещё и
проще, без риска самопересечения при экстремальных параметрах.

**Расширение верхней части** (`Расширение_верхней_мм`,
`Расширение_протяжённость_доля`, из более ранней правки) осталось
без изменений: после подрезки сверху внешняя поверхность у самого
верхнего края плавно "раздаётся" наружу (гладкий cos-колокол, как и
в Группе 2) для более мягкого перехода к приёмной гильзе/коленному
модулю. Реализовано шагом **1b** между подрезкой (1) и расчётом
внутренних точек (3) — внутренняя поверхность считается уже от
РАСШИРЕННОЙ внешней, так что толщина стенки остаётся постоянной и
после расширения.

## Назначение

Превращает облако точек-сечений из Группы 2 в СПЛОШНУЮ ПЕЧАТАЕМУЮ
оболочку: с заданной толщиной стенки, с подрезкой по высоте (снизу —
под нестандартный стык со стопой, сверху — под приёмную гильзу/
коленный модуль), и с делением на переднюю и заднюю половины.

Результат каждой половины — **watertight** (полностью замкнутый,
без единого открытого ребра) меш: именно такая геометрия нужна
слайсеру, чтобы напечатать корректную сплошную стенку, а не "рваную"
поверхность.

## Архитектура: 4 вложенные группы

В отличие от Групп 1-2 (одно плоское дерево), Группа 3 разложена на
**4 отдельные Geometry Nodes группы**, вызывающие друг друга —
классический приём "не повторяться" (DRY), раз одна и та же операция
(построить прямоугольный кусок сетки, сшить два контура) нужна
по 6-10 раз с разными параметрами:

```
NK.3_Оболочка (верхний уровень, узлы 3.xx)
 │
 ├─ вызывает 2 раза → NK.3a_Половина_оболочки (узлы 3a.xx)
 │                       │
 │                       ├─ вызывает 10 раз → NK.3z_Сетка_по_индексам (узлы 3z.xx)
 │                       └─ вызывает 4 раза  → NK.3y_Мост (узлы 3y.xx)
```

## 1) `NK.3z_Сетка_по_индексам` — переиспользуемый "конструктор сетки"

Берёт прямоугольный диапазон (ряды × столбцы) из облака точек
"N колец × M точек на кольцо" (в котором индекс точки =
`ряд*M + столбец`, ровно как формирует Группа 2) и строит меш-сетку
той же формы, где позиция каждой вершины взята из облака по
вычисленному индексу.

**Столбец автоматически "заворачивается" по модулю M** — благодаря
этому один и тот же узел одинаково годится и для вырезания ЦЕЛОГО
кольца, и для открытой ПОЛОСЫ (например, колонки 16..32 у M=32 —
последняя "виртуальная" колонка 32 через modulo превращается в
реальную колонку 0, то есть корректно замыкает шов).

| № | Узел | Формула/роль |
|---|---|---|
| `3z.01` | Group Input | `Точки`, `M_источника`, `Row_от/до`, `Col_от/до` |
| `3z.02-04` | `Math` x3 | `num_cols = (Col_до - Col_от) + 1` → Int |
| `3z.05-07` | `Math` x3 | `num_rows = (Row_до - Row_от) + 1` → Int |
| `3z.08` | `Mesh Grid` | сетка-донор: **Vertices X = num_rows, Vertices Y = num_cols** (см. врезку ниже про порядок осей) |
| `3z.09-13` | `Input Index` + `Math` x4 | из индекса вершины донора получить `(local_row, local_col)` |
| `3z.14-19` | `Math` x6 | `src_row=Row_от+local_row`, `src_col=(Col_от+local_col) mod M_источника`, `src_index=src_row*M+src_col` → Int |
| `3z.20` | `Sample Index` (+`3z.20p` Input Position) | взять `Position` точки-источника по `src_index` |
| `3z.21` | `Set Position` | записать эту позицию на сетку-донор → `Mesh` |

**Грабли Mesh Grid, на которые я сам наступил:** вершины `Mesh Grid`
идут НЕ построчно, а "по столбцам" — индекс = `X_индекс * Vertices_Y
+ Y_индекс`. Чтобы получить привычный построчный порядок (ряд-майор,
как в Группе 2), нужно поменять местами оси: **Vertices X = число
рядов, Vertices Y = число столбцов**. Проверено тестовым скриптом на
известной сетке 4×3 перед использованием в проекте.

Техника целиком проверена отдельным тестом: сэмплинг подмножества
1536-точечного облака (48×32) даёт побитово те же координаты, что и
прямое чтение исходных точек по тем же индексам.

## 2) `NK.3y_Мост` — переиспользуемый "мостик" между двумя контурами

Берёт два одинаковых по длине (`K` точек) набора точек — контур A и
контур B, в одинаковом порядке — и строит между ними полосу
quad-граней. Это один "шов" оболочки: низ, верх, левый или правый
боковой край.

| № | Узел | Формула/роль |
|---|---|---|
| `3y.01` | Group Input | `Точки_A`, `Точки_B`, `K` |
| `3y.02` | `Mesh Grid` | сетка-донор 2×K (2 ряда = "который контур", K столбцов) |
| `3y.03-08` | `Input Index` + `Math` x5 | `which_loop` (0=A/1=B) и `local_idx` из индекса вершины |
| `3y.09` / `3y.10` | `Sample Index` x2 (+ `Input Position` x2) | позиция из контура A / из контура B по `local_idx` |
| `3y.11` | `Math` LESS_THAN | `which_loop < 0.5` → это ряд A? |
| `3y.12` | `Switch` (Vector) | если ряд A → позиция A, иначе → позиция B |
| `3y.13` | `Set Position` | записать на сетку-донор → `Mesh` |

Проверено тестом: 2 контура по 4 точки (Z=0 и Z=10) дают полосу из
8 вершин и 3 quad-граней в ожидаемых местах.

## 3) `NK.3a_Половина_оболочки` — одна замкнутая половина

Строит ОДНУ половину (перед ИЛИ зад — какую именно, определяют
входные `Колонка_от`/`Колонка_до`): внешняя поверхность + внутренняя
(смещённая внутрь на толщину стенки, с перевёрнутыми нормалями) + 4
моста (низ, верх, левый шов, правый шов), сшивающие их в замкнутый
объём.

| Раздел | № узлов | Что делает |
|---|---|---|
| 0. Вспомогательные величины | `3a.02-03ki` | `Nm1=N-1`, `K=Колонка_до-Колонка_от+1` |
| 1. Основные полосы | `3a.04-06` | `outer_main` = `Сетка(Внешние_точки, Row[0..Nm1], Col[от..до])`; `inner_main` = то же по `Внутренние_точки`, затем `Flip Faces` (нормали внутрь) |
| 2. Мост снизу | `3a.07-09` | вырезать ряд `Row=0` у внешней и внутренней полосы, сшить `Мостом` — закрывает нижнюю подрезку |
| 3. Мост сверху | `3a.10-12` | то же для `Row=Nm1` — закрывает верхнюю подрезку |
| 4. Шов "Колонка_от" | `3a.13-15` | вырезать столбец `Col=Колонка_от` (все ряды) у внешней/внутренней, сшить `Мостом` |
| 5. Шов "Колонка_до" | `3a.16-18` | то же для `Col=Колонка_до` |
| 6. Сборка + сварка + разворот нормалей | `3a.19`, `3a.19b`, `3a.19c` | `Join Geometry` всех 6 кусков, `Merge by Distance` (0.01 мм), **`Flip Faces`** |
| 7. Проверка замкнутости | `V3a.1-4` | см. ниже |

**Грабли №1:** `Join Geometry` НЕ сваривает
совпадающие по позиции вершины разных кусков — внешняя полоса и
мост, например, построены НЕЗАВИСИМЫМИ вызовами `Sample Index`, и
хотя геометрически их края совпадают день-в-день, для Blender это
разные вершины меша. Без сварки каждый шов формально остаётся
"дырой" (граничное ребро с 1 гранью вместо 2). Обнаружено это было
именно проверкой `V3a` (см. ниже) — до добавления `Merge by Distance`
все 4 тестовых кейса показывали `Провер_ВСЕ_OK = False` с 512
"дырявыми" рёбрами на половину; после добавления узла `3a.19b` —
`0` дырявых рёбер.

**Грабли №2 (найдены позже, при сборке Группы 4 — задним числом
исправлены здесь):** несмотря на 0 "дырявых" рёбер и правильную
эйлерову характеристику (`В-Р+Г=2`), собранная половина оказалась
**вывернута нормалями внутрь**. Ни проверка замкнутости, ни
характеристика Эйлера этого не ловят — это чисто топологические
инварианты, они не знают про направление нормалей. Баг обнаружился
только когда Группа 4 попыталась сделать `Mesh Boolean`
UNION/DIFFERENCE с этой оболочкой (для хомутов и магнитов) — буленовы
операции существенно зависят от согласованного направления нормалей
("что снаружи, что внутри"), и с вывернутой оболочкой давали "дырявые"
края уже ПОСЛЕ буленовой операции. Диагностировано через
`bmesh.calc_volume(signed=True)` — знак объёма был **отрицательным**
(должен быть положительным для корректно ориентированной замкнутой
поверхности). Исправлено одним узлом `3a.19c` (`Flip Faces`) в самом
конце сборки половины — после фикса объём положительный, и Группа 4
собирается без единого дырявого ребра.

**Вывод для дальнейшей разработки:** "0 граничных рёбер" — необходимое,
но НЕ достаточное условие корректной оболочки. Перед тем, как что-то
буленовое (Группа 4 и далее) применять к новой геометрии, стоит
дополнительно проверять знак `bmesh.calc_volume(signed=True)`.

### Проверка замкнутости (V3a.1 - V3a.4)

| № | Узел | Формула |
|---|---|---|
| `V3a.1` | `Edge Neighbors` | число граней на каждом ребре меша |
| `V3a.2` | `Compare` (INT, NOT_EQUAL) | ребро "граничное" (не 2 соседа) |
| `V3a.3` | `Attribute Statistic` (домен EDGE) | сумма граничных рёбер по всему мешу |
| `V3a.4` | `Compare` (FLOAT, EQUAL 0) | **`Провер_Замкнуто_OK`** = сумма равна нулю |

Дополнительная математическая проверка "на бумаге": для замкнутой
поверхности без дырок и ручек (топологический шар) характеристика
Эйлера `Вершины - Рёбра + Грани = 2`. Для кейса по умолчанию:
`1632 - 3260 + 1630 = 2` ✓ — подтверждает, что оболочка не просто
"без открытых рёбер", а действительно топологически правильная
замкнутая поверхность (без случайно образовавшихся внутренних дыр
или самопересечений, которые тоже дали бы 0 граничных рёбер, но
неверную эйлерову характеристику).

## 4) `NK.3_Оболочка` — верхний уровень

| Раздел | № узлов | Что делает |
|---|---|---|
| 1. Подрезка по высоте | `3.02-07` | читаем `ring_T` каждой точки (атрибут из Группы 2), оставляем точки с `Подрезка_снизу_доля ≤ ring_T ≤ 1-Подрезка_сверху_доля`, остальные удаляем (`Delete Geometry`, домен POINT) |
| 1b. Расширение верхней части | `3.07f1-3.07b` | гладкий cos-колокол от верхнего края (`falloff_верх(T)`, как икра/овальность в Группе 2), `Внешние_точки` (`3.07b`) = подрезанные + `dir*falloff*Расширение_верхней_мм` |
| 2. N после подрезки | `V3.1a`, `3.08-09`, `V3.1b-1` | `N = точек_после_подрезки / Точек_в_кольце`; проверка `V3.1`: остаток от деления == 0 (подрезка убирает только ЦЕЛЫЕ кольца, не режет кольцо пополам — гарантировано тем, что `ring_T` одинаков для всех точек кольца) |
| 3. Внутренние точки | `3.10-13` | `Внутренние_точки` (номинальные) `= Внешние_точки(расшир.) - dir*Толщина_стенки_мм` |
| 4. Граница половин | `3.14-15` | `M/2` — колонка-разделитель перед/зад |
| 5. Две половины | `3.16-17` | `Перед = NK.3a(Col 0..M/2)` и `Зад = NK.3a(Col M/2..M)`, обе из одних и тех же (`3.07b`, `3.13`) — без паза/фальца на шве (см. "Ревизия 220926" выше) |
| 6. Итог | `3.18-19`, `V3.2-3` | `VIS_Вместе = Перед+Зад`; `Провер_ВСЕ_OK` = делимость И обе половины замкнуты; текстовый отчёт |

## Про толщину стенки: важное упрощение

Внутренняя поверхность считается как `Внешняя_точка - dir * Толщина`,
где `dir` — то самое единичное радиальное направление точки из
Группы 2. Это **не** строгая эквидистанта (истинная offset-поверхность
вдоль НОРМАЛИ к поверхности), а её приближение вдоль радиуса
кольца. Для тонкой стенки (2-4 мм) на плавной форме голени (радиус
кривизны — десятки миллиметров) разница между "вдоль радиуса" и
"вдоль истинной нормали" пренебрежимо мала — так же, как в Группе 2,
где `dir` уже использовался для позиционирования точек. Если в
будущем понадобится безупречная эквидистанта — можно заменить `dir`
на честную нормаль поверхности (`Input Normal` уже посчитанную
Blender'ом по факту построенной оболочки), но это потребует
дополнительного прохода (сначала построить оболочку БЕЗ толщины,
взять её нормали, потом сдвинуть).

половины по отдельности) с 0 незамкнутых рёбер — после удаления
фальца (правки 220926) bbox по X у `default` больше не зависит от
утопления шва (раньше `joint_off` без утопления давал X на 0.6мм
больше, чем `default` с утоплением — теперь такой развилки просто
нет, у всех кейсов одна и та же номинальная геометрия шва).

Проверка "на глаз": в кейсе `trimmed` высота упала с 350 до 253.4 мм
— близко к ожидаемым `350*(1-0.15-0.10)=262.5` мм (небольшая разница
из-за того, что подрезка "прилипает" к ближайшим существующим
кольцам, шаг между которыми ≈7.4 мм при разрешении 48).

Дополнительно для каждого кейса проверена эйлерова характеристика
(`В-Р+Г=2`) через прямой bmesh-анализ в Python — подтверждает, что
это не просто "0 открытых рёбер", а честная замкнутая поверхность
без дыр и самопересечений.

Визуальное подтверждение (`renders/group3_*.png`):
- `group3_default.png` — вид сбоку: убедительный силуэт голени с
  выступом икры вверху и сужением к лодыжке внизу.
- `group3_trimmed.png` — тот же вид с подрезкой: видны ровные плоские
  срезы сверху и снизу (закрытые "мостами", не дыры).
- `group3_EXPLODED_TOP.png` — вид сверху, половины раздвинуты для
  наглядности: у каждой половины отчётливо видна толщина стенки на
  срезе — обе половины действительно замкнутые сплошные оболочки, а
  не тонкие "скорлупки".

## Известные упрощения и ограничения

- `Точек_в_кольце` (M) должно быть **чётным** — иначе `M/2` округлится
  и передняя/задняя половины будут отличаться на одну колонку
  (не критично, но лучше держать чётным; по умолчанию 32).
- Подрезка по высоте "прилипает" к существующим кольцам Группы 2 —
  точность подрезки равна шагу между кольцами (`Длина/Разрешение`,
  по умолчанию ≈7.3 мм). Для более точной подрезки увеличьте
  `Разрешение` в Группе 1.
- Толщина стенки — приближение вдоль радиуса, а не истинная
  эквидистанта (см. раздел выше).
- Швы (левый/правый боковые края половин) остаются номинальной
  геометрией стенки, БЕЗ какого-либо интерлока/паза и БЕЗ отдельных
  элементов крепежа (Группа 4 "Закладные" с хомутами/магнитами
  полностью удалена из проекта, см. `docs/00_overview.md`) — половины
  держатся вместе только клеем/посадкой встык.

## Как проверить самостоятельно в Blender 5.1

1. Открыть `builds/group3_shell.blend`, объект `NK_Group3_Demo`.
2. В модификаторе — три вложенных `Group`: Группа 1 → Группа 2 →
   Группа 3. Покрутите `Подрезка_снизу_доля`/`Подрезка_сверху_доля`/
   `Толщина_стенки_мм` внутри узла Группы 3 — форма должна на лету
   подрезаться и менять толщину стенки.
3. Зайдите внутрь `NK.3_Оболочка` (Tab) — увидите 6 пронумерованных
   рамок (1-6), а внутри узлов-`Group` `NK.3a_Половина_оболочки` можно
   зайти ещё на уровень глубже (Tab ещё раз) и увидеть 10 вызовов
   `NK.3z_Сетка_по_индексам` и 4 вызова `NK.3y_Мост`.
4. Чтобы увидеть `Перед`/`Зад` по отдельности — временно подключите
   соответствующий выход группы к выходу модификатора вместо
   `VIS_Вместе`.
